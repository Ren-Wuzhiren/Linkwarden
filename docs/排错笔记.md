# 排错笔记

> 记录真实故障、现象、定位过程、根因和修复结论。只记录实际发生的问题。

## 2026-09-12 Docker 拉取 Meilisearch 返回 502

- 现象：首次 `docker compose up` 时，`dockerproxy.net` 返回 502，PostgreSQL 镜像拉取也被中断。
- 定位：Docker `RegistryConfig.Mirrors` 配置为 `https://dockerproxy.net/`。
- 处理：不立即修改全局 Docker 配置，先执行 `docker compose pull` 重试；第二次拉取成功。
- 结论：镜像加速器的 502 可能瞬时出现，先重试并确认是单次故障，再考虑调整全局配置。

## 2026-09-12 PostgreSQL 无法绑定 5433

- 现象：Docker 端口映射到宿主 `5433` 时报 `bind: An attempt was made to access a socket in a way forbidden by its access permissions`。
- 定位：`netsh interface ipv4 show excludedportrange protocol=tcp` 显示 `5360-5459` 在 Windows 排除区间内。
- 处理：把 PostgreSQL 宿主端口改为 `55432`，同时更新本地 `.env` 的 `DATABASE_URL`。
- 结论：Windows 上 Docker 端口冲突不一定是进程占用，也可能是系统保留区间。

## 2026-09-12 Yarn 4 安装出现 EXDEV

- 现象：Yarn 下载依赖后，把缓存临时文件重命名为正式文件时反复出现 `EXDEV: cross-device link not permitted`。
- 定位：当前目录可见路径都在 C 盘，但用户 AppData 目录带加密/重解析环境；Corepack 包装进程仍使用默认全局缓存。
- 处理：使用 Node 20 直接调用 `reference/tools/corepack/v1/yarn/4.12.0/yarn.js`，并设置 `YARN_CACHE_FOLDER` 到 D 盘、`YARN_ENABLE_GLOBAL_CACHE=false`。
- 结果：依赖安装完成，Prisma Client 生成，patch-package 和 Playwright Chromium 安装成功。

## 2026-09-12 Next.js 启动出现 EXDEV

- 现象：Next.js 启动时写 `AppData\Roaming\nextjs-nodejs\Config\config.json` 失败，web 进程退出。
- 根因：Next.js telemetry 配置写入路径触发了同类跨卷重命名问题。
- 处理：设置 `NEXT_TELEMETRY_DISABLED=1` 后重启。
- 结果：Next.js 在 2.1 秒内 Ready，`http://localhost:3000` 返回 HTTP 200，worker 四个循环正常启动。

## 2026-09-14 Docker 提示找不到 dockerDesktopLinuxEngine

- 现象：执行 `docker compose -f deploy/local/docker-compose.yml up -d` 时提示 `npipe:////./pipe/dockerDesktopLinuxEngine` 不存在。
- 定位：Docker CLI 正常，但 Docker Desktop 进程没有运行，WSL 中的 `docker-desktop` 发行版处于 `Stopped`，因此 Compose 路径和 YAML 都没有问题。
- 处理：通过可见窗口启动 Docker Desktop，等待 `docker info` 可以读取 Server 版本后重新执行 Compose。
- 结论：先验证 `docker info`，再验证 Compose；不要把 daemon 未启动误判为 Compose 文件路径错误。

## 2026-09-14 Docker Hub 直连拉取镜像超时

- 现象：引擎启动后，`mysql:8.4` 和 `redis:7.4-alpine` 拉取时连接 `registry-1.docker.io:443` 超时。
- 定位：Docker 当前没有配置 registry mirror，本地已有版本匹配的缓存镜像。
- 处理：确认缓存镜像分别是 MySQL 8.4.11 和 Redis 7.4.11，并给它们补齐 `mysql:8.4`、`redis:7.4-alpine` 本地标签后启动。
- 结果：MySQL 与 Redis 容器均达到 `healthy`；Compose 文件仍使用标准镜像名，不绑定当前机器的特殊标签。
