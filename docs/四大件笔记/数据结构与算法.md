## 阶段 1.2：标识与关联

已观察到的真实实现：

- `requestId` 用 UUID 作为缺失或非法请求头时的替代标识。
- UUID 的设计目标是实际使用中极低碰撞概率，不等于数学意义上的绝对唯一，也不能作为安全凭证。
- `ThreadLocal` 把同一个请求 ID 与当前处理线程关联起来，但本阶段没有研究 `ThreadLocalMap` 的底层结构。

## 阶段 1.4：规范化、唯一性与索引

已通过代码和数据库验证：

- 用户名和邮箱在进入校验与持久化前先规范化：`strip()` 处理首尾空白，邮箱固定用 `Locale.ROOT` 小写化，空白邮箱转成 `null`。
- 规范化必须发生在校验之前，否则“输入时长度为 6、规范化后长度为 2”的字符串会绕过长度规则；这体现了数据表示顺序会影响算法正确性。
- `app_user.username` 和 `app_user.email` 的 `UNIQUE KEY` 由数据库索引承担并发下的唯一性最终保障，业务层的先查询再插入不能替代它。
- `email = NULL` 允许重复，是因为 SQL 唯一索引对 `NULL` 的语义与普通值不同；这属于数据模型约束，不是简单的集合去重。

当前边界：

- 还没有实现 URL 哈希、ngram 全文检索或任务队列去重，后续阶段再补充对应的数据结构和复杂度分析。

## M2.1–M2.4：复合主键、比较语义与查询次数

| 里程碑 | 本节取用的真实产物 |
| --- | --- |
| `M2.2` | tag 表的唯一约束与 `utf8mb4_0900_ai_ci` 排序规则 |
| `M2.3` | link 表、两条级联外键、集合非空拒删的计数查询 |
| `M2.4` | `link_tag` 联合主键、标签替换写入、标签归属校验 |

已通过代码和测试验证：

- `link_tag` 用联合主键 `(link_id, tag_id)`，表上没有代理主键；这一个键同时表达“同一对不许出现两次”和“按 `link_id` 查最快”。
- MyBatis-Plus 只认单主键：不给 `LinkTag` 声明 `@TableId` 时框架启动会打 `Can not find table primary key in Class` 的 WARN。
- 把 `link_id` 声明成逻辑主键只是让框架安静下来的权宜之计，代价必须写进代码：这张表禁用 `selectById`、`deleteById`、`updateById`。
- 这三个方法都按 `link_id` 匹配，`deleteById` 会把该链接的全部关联一次删光，所以本表所有条件一律走 `LambdaQueryWrapper`。
- 标签名的“相等”由排序规则 `utf8mb4_0900_ai_ci` 决定，不是字符串本身的属性：`Java` 与 `java` 在数据库看来是同一个名字。
- 查重条件里出现 `ne(列, null)` 时结果恒为 unknown，查重会恒返回 0，于是“排除自身”的测试会假通过——假通过比报错更难发现。
- 标签 id 去重用 `LinkedHashSet`：既去掉重复，又保留客户端给的顺序，便于调试和断言。
- 校验“这批标签全部归我”用一次 `IN` + `COUNT` 比对条数，而不是逐个查询，查询次数从 O(n) 降到 O(1)。
- 集合与标签列表的 `linkCount` 目前是已知的 N+1：列表有几个元素，就多查几次计数。

```text
link_tag 的联合主键 (link_id, tag_id)                    → V5__create_link_tag.sql
LinkTag 的 @TableId(value = "link_id", type = INPUT)      → LinkTag.java
本表禁用 selectById / deleteById / updateById             → LinkTagMapper.java
utf8mb4_0900_ai_ci：Java 与 java 视为同名                 → TagMapperTest
ne(列, null) 恒为 unknown，查重恒返回 0                   → TagMapperTest.shouldNeverMatchWhenExcludingNull
LinkedHashSet 去重保序                                   → LinkService.distinctTagIds
一次 IN + COUNT 校验标签归属                              → LinkService.assertOwnedTags
linkCount 的 N+1                                         → TagService.listTags、CollectionService.listCollections
```

- 复合主键的最左前缀只做了原理说明，没有用 `EXPLAIN` 实测索引命中情况。
- ngram 全文检索与任务队列去重仍留在后续阶段。
