# 计算机组成原理

> 从本项目真实实现中反哺计算机组成原理知识；没有实际经历前不虚构结论。

## 待项目验证

- 浏览器渲染、PDF/图像生成的资源消耗。
- 文件 I/O、缓存与内存缓冲。

## 阶段 1.2：从源码到 JVM

已观察到的真实过程：

- Maven 把 Java 17 主代码编译到 `target/classes`，把测试代码编译到 `target/test-classes`。
- Spring Boot 启动后由 JVM 加载应用类和依赖，随后启动内嵌 Tomcat 并监听 8080 端口。
- 阶段 1.2 首次验证时 `mvn -pl backend test` 报告 6 个测试通过；截至 2026-09-27 已增长到 55 个测试通过，说明主代码、测试代码和依赖 classpath 持续协同工作。

当前边界：

- 还没有直接观察 CPU、缓存、指令流水或内存带宽层面的现象。
- 后续 Playwright 截图、PDF 和图像处理阶段再记录资源消耗与文件 I/O。

## 阶段 1.4：JVM、外部容器与密码哈希

已通过代码或日志验证：

- Maven 分别编译主代码和测试代码，Spring Boot 测试进程通过 JDK 17 启动，再由 `@DynamicPropertySource` 注入 Testcontainers 暴露的随机端口。
- MySQL 和 Redis 运行在独立容器中，Java 测试进程通过 TCP 端口访问它们；这是进程隔离和 I/O 边界的真实例子。
- BCrypt 不是普通字符串比较，它通过可调工作因子增加计算成本；当前测试只验证编码和匹配正确性，没有做性能基准。

当前边界：

- 尚未测量 CPU、内存、磁盘吞吐或浏览器渲染成本，不能把“密码哈希有计算成本”扩展成未经验证的性能结论。
