## 一、项目属性关键词

判定依据全部是可核对的仓库内路径。

| 关键词 | 判定依据 |
| --- | --- |
| **全栈 Web** | 前端 React 19 + Next.js `15.5.21`，使用 Pages Router；页面（`apps/web/pages/*.tsx`）与 REST API（`apps/web/pages/api/v1/**`）在**同一个进程**里对外提供服务 |
| **模块化单体（Modular Monolith）** | 单镜像、单端口 `3000`；模块靠 `apps/*` + `packages/*` 两层切分；`docker-compose.yml` 里只有基础设施容器，没有服务间 RPC，**不是微服务** |
| **Web / Worker 双进程** | `Dockerfile` 的 `CMD` 用 `concurrently` 在同一个容器里同时拉起 `next start` 和 `tsx worker.ts`；二者共享同一份 `node_modules` 和同一个数据库 |
| **多端生态 Monorepo** | Yarn 4 workspaces（根 `package.json` 的 `workspaces: ["apps/*", "packages/*"]`）；`apps/` 下共 4 个可运行终端 |
| **自托管优先** | `docker-compose.yml` 只依赖 postgres:16 + meilisearch:1.13 两个外部服务；`.env.sample`（489 行）是全部配置入口 |
| **Web 归档引擎** | Playwright 负责截图与 PDF，Mozilla Readability 负责正文抽取，Rust 二进制 monolith 负责单文件 HTML，见 `apps/worker/lib/preservationScheme/` |
| **协作型多租户** | `packages/prisma/schema.prisma` 中的 `UsersAndCollections` 模型带 `canCreate / canUpdate / canDelete` 三个权限位，且有 `Collection.isPublic` 标记 |
| **商业 + 开源双轨** | 代码里同时存在 Stripe、Apple App Store 与 Google Play 的订阅计费：`Subscription` 模型 + `apps/web/lib/api/billing/` |
| **AI 增强** | `apps/worker/package.json` 依赖 `@ai-sdk/openai-compatible`、`@ai-sdk/anthropic`、`@ai-sdk/azure`、`@ai-sdk/perplexity`、`@openrouter/ai-sdk-provider`、`ollama-ai-provider-v2`；`Link.aiTagged` 字段标记打标状态 |
| **非 Agent 项目**（易误判，需明确纠正） | 没有 LLM 决策循环、没有工具调用、没有规划器、没有多轮自主执行。AI 的唯一用途是「给链接生成标签」，属于**功能增强**而非产品主体。"用了 AI SDK" 不等于"是 Agent 项目" |
| **国际化（i18n）** | `apps/web/public/locales/` 下有 15 个语言目录（含 `zh`、`zh-TW`），配合根目录 `crowdin.yml` |
| **非 CLI / 非控制台工具** | 没有 TUI 或终端交互形态，对外形态是浏览器 UI + REST API，另有独立仓库的浏览器扩展 |
| **强外部世界容错** | `apps/worker` 大量使用可配置上限与超时：`BROWSER_TIMEOUT`、`PDF_MAX_BUFFER`、`SCREENSHOT_MAX_BUFFER`、`READABILITY_MAX_BUFFER`、`MONOLITH_MAX_BUFFER`、`TEXT_CONTENT_LIMIT`、`AUTOSCROLL_TIMEOUT` |

**一句话属性串**：

```text
TypeScript 全栈 · 模块化单体 · Web + Worker 双进程 · 自托管 · 多端 Monorepo
· Web 归档引擎 · 协作型多租户 · 商业开源双轨 · AI 增强但非 Agent · 非 CLI
```

## 二、项目规模评估

### 统计口径

- 范围：`apps/` 与 `packages/` 两棵树。
- 文件类型：`.ts` 与 `.tsx`。
- 排除：`node_modules/`、`.next/` 构建产物。

### 模块级体量

| 模块 | 代码文件数 | 代码行数 | 说明 |
| --- | ---: | ---: | --- |
| `apps/web` | 330 | 30,355 | 主站，占比最大 |
| `apps/mobile` | 82 | 11,638 | Expo / React Native 移动端 |
| `apps/extension` | 44 | 4,082 | 浏览器扩展（另含 Safari 的 Xcode 工程） |
| `apps/worker` | 26 | 2,132 | 异步归档引擎；**代码最少但密度最高** |
| `packages/router` | 14 | 2,425 | Web 与移动端共享的 API 客户端 |
| `packages/lib` | 19 | 1,289 | SSRF 防护、搜索客户端、公共工具 |
| `packages/filesystem` | 11 | 467 | 本地磁盘与 S3 的统一存储抽象 |
| `packages/prisma` | 2 | 19 | 仅 re-export 入口与生成类型（见下方说明） |
| `packages/types` | 2 | 230 | 跨应用共享类型 |
| **合计** | **530** | **52,637** | |

补充说明：`packages/prisma` 的口径容易误读。按 `.ts` 统计只有 19 行，因为真正的数据模型定义在 **`schema.prisma`（324 行）**，种子数据在 **`seed.js`（1,251 行）**，另有 Prisma 生成的客户端。这三者都不计入上表的业务代码行数。

### 其他体量指标

| 指标 | 数值 |
| --- | ---: |
| 全仓库文件（`apps/` + `packages/`，排除 `node_modules`） | 753 |
| Prisma 数据模型（表） | 15 |
| 数据库迁移目录 / SQL 文件 | 99 |
| 迁移时间跨度 | 2023-07-19 → 2026-08-18（3 年多） |
| vitest 单元测试文件（`.test.ts` / `.test.tsx`） | 11 |
| Playwright 端到端用例（`.spec.ts`） | 1，另有 2 个 setup 与 6 个 fixture/数据文件 |
| `.env.sample` 行数 | 489 |
| 其中 SSO 提供方开关（`NEXT_PUBLIC_*_ENABLED`） | 61，另有 1 个通用 OIDC |

### 规模结论：中型偏大

判定理由：

1. **单端就不小**：主站 `apps/web` 一个模块 3 万行，已超出「一个人一个周末」的量级。
2. **端太多**：4 个可运行终端 + 5 个共享库，跨端一致性是主要复杂度来源，也是 monorepo 存在的理由。
3. **有真实演化年限**：99 个迁移跨越 3 年，包含大量 `rename_field` / `remove_field`。**这是"中型"最诚实的证据，而不是行数。**
4. **但它不是大型**：没有微服务、没有消息中间件、没有 K8s；依赖关系是清晰的扁平两层（`apps/*` → `packages/*`），没有循环依赖。

参考系对比：

```text
Java 单体练习项目        小型
本项目 WebCollector MVP   中小型
Linkwarden v2.16.3        中大型
企业级平台 / 微服务集群    大型
```

## 四、技术亮点清单

按「解决了什么现实问题」排序，而不是按代码量排序。

| # | 亮点 | 解决了什么问题 | 证据文件 |
| ---: | --- | --- | --- |
| 1 | **SSRF 三层防护** | 服务端抓取用户提供的 URL 会把内网暴露给外部。上游在三个层面拦截：保存时预检、Playwright 子请求拦截、外部进程走本地代理 | `packages/lib/ssrf.ts`、`apps/worker/lib/protectPageRequests.ts`、`apps/worker/lib/ssrfProxy.ts` |
| 2 | **`"unavailable"` 三态哨兵** | 资产字段若只用 `null`，就无法区分「还没尝试」和「尝试过但失败」，会导致无限重试。上游用 `null` / 真实路径 / `"unavailable"` 三态表达 | `apps/worker/lib/archiveHandler.ts` 的 `finally` 段 |
| 3 | **队列即表（无独立任务表）** | 用 `Link.lastPreserved IS NULL` 表示「待归档」，省掉一整套任务表与中间件，部署只要 Postgres | `apps/worker/lib/getLinkBatchFairly.ts`、`apps/web/lib/api/controllers/links/postLink.ts` |
| 4 | **公平批调度，防饿死** | 朴素 `ORDER BY created_at LIMIT n` 会让批量导入的单用户饿死整个队列。上游按用户轮转分摊批次，并用 `lastPickedAt` 记录最近被处理的用户 | `apps/worker/lib/getLinkBatchFairly.ts`（`lastPickedAt`、`nulls: "first"`） |
| 5 | **归档方案可插拔** | 每种资产一个独立 `handleXxx`，签名统一、互不干扰；某一种失败不影响其他（`Promise.allSettled`）。这是 Strategy 模式的实际应用 | `apps/worker/lib/preservationScheme/` |
| 6 | **两级归档策略** | 默认策略挂在用户身上，但可以被标签覆盖。合并规则在归档时计算 | `archiveHandler.ts` 中的 `archivalTags.length > 0 ? 标签配置 : 用户配置`，配合 `packages/lib/isArchivalTag.ts` |
| 7 | **跨端共享 API 客户端** | Web 与移动端各写一份请求代码会长期漂移。上游把请求层抽成包，两端共用同一份实现 | `packages/router/`（被 `apps/web` 和 `apps/mobile` 同时依赖） |
| 8 | **浏览器生命周期工程化** | 浏览器启动昂贵但不能常驻（会泄漏）。上游提供 on-demand 与 persistent 两种模式、30 分钟强制轮换、60 秒空闲回收 | `apps/worker/workers/linkProcessing.ts`（`BROWSER_LIFECYCLE`、`BROWSER_MAX_AGE_MS`） |
| 9 | **进程监督 + 任务级自愈** | 双保险：进程级崩溃自动重启，任务级检测浏览器断连后换新实例，当前批次不整体失败 | `apps/worker/index.ts`（`child.on("exit")` → 5 秒重启）、`linkProcessing.ts`（`browser.isConnected()`） |
| 10 | **资产授权下沉到路径解析** | 若先拼路径再判权限，容易漏判导致越权读文件。上游先判集合权限（owner / member / public），**权限不过就根本拼不出路径** | `apps/web/lib/api/archives/resolveAccessibleArchive.ts` |
| 11 | **三阶段 Docker 构建** | 归档需要 Rust 二进制，但运行镜像不该带 Rust 工具链。构建层产出 monolith 可执行文件，运行层只装 `chromium-headless-shell`，最终约 400 MB | `Dockerfile`（`monolith-builder` → `app-builder` → `main-app`） |
| 12 | **限制全集环境变量化** | 超时与大小上限若写死在代码里，运维无法按机器规格调优。上游把 buffer 上限与超时全部做成环境变量 | `.env.sample` 中的 `*_MAX_BUFFER`、`BROWSER_TIMEOUT`、`AUTOSCROLL_TIMEOUT`、`TEXT_CONTENT_LIMIT` |

## 五、复杂度来源

理解「为什么它看起来这么大」，可以避免把项目规模判断错。

1. **端多**。同一个业务模型要服务 Web / Worker / 扩展 / App 四种消费方式，因此必须抽出 `packages/types` 与 `packages/router`。这不是过度设计，是跨端的必然代价。
2. **年限长**。99 个迁移里有大量 `rename` / `remove_field`，属于**演化遗留**而非设计缺陷。新人看到 15 张表，其实核心只有 5 张：`User`、`Collection`、`Link`、`Tag`、`Highlight`。
3. **多租户 + 计费**。一旦引入协作与付费（`UsersAndCollections` 的权限位、`Subscription`），鉴权就从「查一次 ownerId」升级为「owner → 成员 → 公开」三层判定，见 `getPermission.ts` 与 `resolveAccessibleArchive.ts`。
4. **外部世界不可控**。目标网页会超时、会弹 Cookie 墙、会有无限滚动、会返回巨图。因此才有 `unavailable` 兜底、各类 buffer 上限、自动滚动和超时竞速。
5. **可选性爆炸（配置复杂度 ≠ 代码复杂度）**。`.env.sample` 里 61 个 SSO 提供方开关，看起来像巨石，实际只是配置项。**阅读时不要把配置项数量当成项目规模。**

> 一句话总结：Linkwarden 是一个 TypeScript Yarn Monorepo 的**模块化单体**——`apps/web` 出 UI 和 API，`apps/worker` 用 Playwright + Readability + Monolith 组成可插拔的归档流水线，`packages/prisma` 上的 `Link` 表同时充当业务实体和任务队列，`packages/lib` 承担 SSRF 与存储抽象，`packages/router` 把 API 客户端同时供给 Web 和 App。它的技术亮点不在算法，而在**对不可控外部世界的工程化处理**：超时、三态、缓冲区上限、公平调度、进程自愈与三层 SSRF 防护。
