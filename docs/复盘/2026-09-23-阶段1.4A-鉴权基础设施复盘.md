# 阶段 1.4A 复盘：鉴权基础设施

## 本轮目标

在 `app_user` 迁移和统一错误协议的基础上，建立后续注册、登录、`/me`、退出共同复用的鉴权基础设施，但暂不实现四个 HTTP 接口。

## 方案确认

- 采用 Sa-Token + Redis 持久化会话，不引入 JWT。
- Token 使用 `Authorization: Bearer <token>`，只从请求头读取。
- Token 是不透明字符串，Redis 保存服务端会话状态，因此退出可以立即让原 Token 失效。
- JWT 只保留为后续可替换的认证实现练习，不属于第一版必需依赖。

## 已完成

- `backend/pom.xml` 使用 `sa-token-redis-jackson:1.46.0`，不再需要 `sa-token-jwt`。
- `application.yml` 配置 Bearer 前缀、7200 秒有效期、UUID Token、只读请求头和独立会话。
- `application-local.yml` 开启本地注册，公共配置默认关闭注册。
- `AuthProperties` 绑定 `app.auth.registration-enabled`。
- `AuthConfig` 提供只暴露 `PasswordEncoder` 接口的 BCrypt Bean。
- `ErrorCode.AUTH_REQUIRED` 映射为 HTTP 401。
- `GlobalExceptionHandler` 把 `NotLoginException` 固定映射为安全的外部错误，不泄漏 Sa-Token 内部原因。
- `SaTokenRedisIntegrationTest` 验证真实 MySQL 8.4、Redis 7.4 和 `SaTokenDaoForRedisTemplate` 的生命周期。

## 暴露的问题

- Testcontainers 1.21.2 与 Docker Engine 29 的 Java 客户端协商失败，固定到 1.21.4 后恢复。
- Ryuk 镜像直接拉取超时；从可达镜像源拉取并补齐官方标签后，命令行和 IDEA 都不再需要临时禁用 Ryuk。
- 仅在 PowerShell 设置环境变量不能影响 IDEA 自己启动的 JUnit JVM，环境变量类修复不能替代镜像和配置层的根治。
- 手工观察 Redis 时使用 `SCAN`，避免把阻塞式 `KEYS *` 当运维方案。

## 学习收获

- “使用 Token”不等于“使用 JWT”；会话 Token、签名 Token 的状态模型和退出语义不同。
- 认证失败不应该把“没带 Token、过期、注销”等内部细节全部回显给客户端，统一错误码可以同时降低耦合和探测空间。
- 密码编码器应作为依赖注入，业务层依赖 `PasswordEncoder` 契约而不是直接依赖具体实现。
- Redis 中的会话是业务状态的一部分，不是可以随意清空的浏览器缓存。
