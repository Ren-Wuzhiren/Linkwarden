# 阶段 1.4B1 与 1.4B2 复盘：用户映射与注册输入

## 本轮目标

在真实数据库表和鉴权基础设施上，建立用户 Java 映射，并准备注册接口所需的 DTO、用户摘要和输入规范化。注册 Service/Controller 仍留到 1.4B3。

## 已完成

### 1.4B1：用户映射

- `AppUser` 使用 `@TableName("app_user")` 和 `@TableId(type = IdType.AUTO)`。
- `AppUserMapper extends BaseMapper<AppUser>`，由 MyBatis-Plus 动态代理提供实现。
- `MybatisPlusConfig` 增加 `@MapperScan("com.webcollector.**.mapper")`。
- `AppUserMapperTest` 在真实 MySQL 中验证主键回写、逐字段查回和用户名唯一约束。

### 1.4B2：输入模型

- `AuthInputNormalizer` 使用 `strip()` 删除首尾空白，能处理全角空格 `U+3000`。
- 邮箱固定使用 `Locale.ROOT` 小写化，空白邮箱规范化为 `null`。
- `RegisterRequest` 在 record 紧凑构造器中先规范化，再进行 Bean Validation。
- 密码不执行 `strip()`，避免改变用户刻意设置的首尾空格。
- `UserSummary` 只暴露 `id`、`username`、`email`、`createdAt`，从类型层面排除 `passwordHash`。
- `AuthInputNormalizerTest` 6 项和 `RegisterRequestValidationTest` 7 项通过。

## 暴露的问题

- 字段名 `createAt` 少了 `d`，MyBatis-Plus 映射到不存在的 `create_at`，直接在真实插入时失败。
- setter 参数重命名不完整形成 `this.updatedAt = updatedAt` 自赋值，字段保持 `null`；MyBatis-Plus 的 `NOT_NULL` 策略因此没有插入该列，MySQL 报 `updated_at` 没有默认值。
- `String.trim()` 不能删除全角空格，使用 `strip()` 后才覆盖中文输入场景。
- 如果规范化被推迟到 Service，Bean Validation 会先看到未规范化字符串，导致 `"  ab  "` 误通过最小长度校验。

## 学习收获

- 能编译只证明语法和类型正确，不能证明数据库列名、setter 赋值和字段映射正确；真实集成测试是必要证据。
- 命名重写应使用 IDE 的重构工具，避免参数和字段只有一半被修改。
- 校验、规范化和持久化必须对同一个值负责，顺序错误会留下“校验通过但业务不合法”的缝隙。
- 唯一约束的真正最终防线在数据库索引，业务层预检查负责更友好的错误结果。
