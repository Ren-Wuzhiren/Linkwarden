# 2026-10-08 阶段 1.4 与 1.5：登录会话闭环复盘

## 本阶段目标

完成用户从登录到退出这一条真实的鉴权会话链路：

- 登录成功后由 Sa-Token 建立 Redis 会话。
- 客户端使用 `Authorization: Bearer <token>` 访问 `/me`。
- 退出后原 Token 立即失效。
- 重复退出保持幂等。

## 已完成内容

- `SessionTokenService` 和 `SaTokenSessionService`：隔离 `AuthService` 与 Sa-Token 静态 API。
- `LoginRequest`、`LoginResponse`：表达登录输入和 Token 响应契约。
- `AuthService.login`：BCrypt 校验、统一凭证错误和会话建立。
- `AuthService.getCurrentUser`：读取当前登录用户，并在用户不存在时清理会话。
- `AuthService.logout`：委托会话适配器注销当前 Token。
- `AuthController`：完成 `/login`、`/me`、`/logout`。
- `AuthServiceTest`、`AuthControllerTest`：覆盖业务层和 HTTP 层成功、失败及幂等路径。
- `AuthSessionIntegrationTest`：使用真实 MySQL、Redis、BCrypt、Sa-Token 和 MockMvc 验证完整生命周期。

## 关键结论

- `SessionTokenService` 让业务层不依赖 Sa-Token 静态 API，单元测试与真实集成测试的职责更清晰。
- 未登录、未知 Token、退出后的 Token 都统一返回 `401 AUTH_REQUIRED`。
- 用户名不存在和密码错误统一返回 `401 AUTH_INVALID_CREDENTIALS`。
- 退出接口的幂等行为由会话适配器保证。
- 真实 Redis 会话生命周期已经通过 HTTP + Testcontainers 验证，而不是只验证键值读写。
