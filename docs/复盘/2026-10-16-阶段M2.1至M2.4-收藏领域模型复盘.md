## 🧠 关键结论

集合改名的大小写缺陷，根因是 Java 侧用 `getName().equals(...)` 自己比了一次名字。

而数据库的排序规则是 `utf8mb4_0900_ai_ci`，它把 `Java` 和 `java` 视为同一个名字。

两套比较规则不一致时，“只改大小写”的改名会被 Java 拦下、又被数据库认为重名，于是改名失败。

修复不是去改排序规则，而是删掉 Java 侧那次多余的比较，让唯一索引成为唯一的判定者。

`link_tag` 用联合主键 `(link_id, tag_id)`，而 MyBatis-Plus 只认单主键，`LinkTag` 只能把 `link_id` 声明成逻辑主键来消掉启动 WARN。

这个权宜之计的代价必须写进代码：这张表禁用 `selectById`、`deleteById`、`updateById`，因为它们都按 `link_id` 匹配。

`link_tag` 不带 `user_id`，前提是写入时 `assertOwnedTags` 已经强制“这条链接和这批标签同属一人”。

这条不变量一旦被绕过，标签使用数就会跨用户串号，所以它必须留在 `LinkService` 的校验顺序里，而不是靠表结构兜底。
