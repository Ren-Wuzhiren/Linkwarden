## 编号规则

从阶段 1.4 起使用三段式编号：

```text
X.Y.Z
```

- `X`：大阶段。
- `Y`：阶段内的业务阶段或子问题。
- `Z`：该阶段中的一个可验收增量。

不再使用 `1.4B3.1` 这类十进制、字母和点号混排的编号。历史文档和 Git 历史不强制重命名，旧编号映射保留在需求文档索引中。

## 阶段 0：工程基线与环境

这个阶段主要解决：让项目从零散的学习环境变成统一、可构建、可复现的开发与测试基础。

内容包括：

- Maven 聚合工程
- Java 17 与 IDEA 配置
- Spring Boot 基础骨架
- Docker Compose、MySQL、Redis
- Flyway、统一响应、请求 ID、健康检查
- 文档、Git、测试基线

当前状态：已完成。

## 阶段 1：用户与鉴权

这个阶段主要解决：确定“当前请求属于哪个用户”，并建立可撤销的登录会话。

内容包括：

- `app_user`
- BCrypt
- Sa-Token + Redis 会话
- 注册
- 登录
- 当前用户
- 退出
- 权限边界和错误码

当前状态：进行中。`1.4.1`、`1.4.2` 已完成，`1.4.3` 注册接口进行中。

内容包括：

- 默认 Inbox
- 所有权隔离
- URL 规范化
- 重复 URL 处理
- 保存链接时创建 `PENDING capture_job`
