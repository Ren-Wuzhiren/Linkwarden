## 用户与问题

主要用户是作者自己：经常在浏览器、GitHub、博客、课程页和文档站点中发现值得长期保留的内容，但普通书签只保存 URL，无法处理链接失效、页面变化和后续检索。

需要解决的现实问题：

- 收藏后无法保证还能看到当时的内容。
- 资料分散在浏览器书签、笔记和本地文件中。
- 只靠标题和 URL 很难找回旧资料。
- 直接抓取网页涉及超时、失败、重定向和 SSRF 等风险。

## 产品目标

把 URL 保存为一份可检索、可回看的个人资料快照，并让整个保存过程对失败可见、可重试、可复盘。

核心闭环：

```text
保存 URL -> 创建待处理任务 -> Worker 抓取 -> 生成资产
-> 提取正文 -> 建立检索索引 -> 查询和打开快照
```

## 第一版功能

- 用户名密码登录与退出。
- 默认集合和扁平集合管理。
- 标签创建、修改、删除和关联。
- 保存 HTTP/HTTPS 链接。
- 异步生成 HTML、PDF 和全页截图。
- 抽取正文用于阅读和检索。
- 查看任务进度、失败原因和重新采集。
- 按标题、描述、正文、标签和集合搜索。
- 查看原链接、HTML、PDF、截图和正文。

## 明确不做

- 多用户协作、邀请、角色权限。
- 公开分享与匿名访问。
- 浏览器扩展、移动端和浏览器同步。
- AI 标签、摘要和问答。
- RSS、SSO、邮件和计费。
- 嵌套集合、Highlight 批注。
- MinIO/S3 和 Meilisearch。

## 成功标准

- 30 个不同网页的首次保存成功率不低于 90%。
- 从提交 URL 到快照可查看的中位时间不超过 30 秒。
- 失败任务保留错误原因，并且单次失败不会删除已有资产。
- 用户可连续使用 30 天，数据不因重启丢失。
- 核心保存、搜索和查看流程无需查阅文档即可完成。

## 第一阶段交付边界

第一轮编码只完成“登录 + 默认集合 + 保存链接记录 + 任务表”，暂不抓取网页。必须能验证鉴权、数据库迁移、接口契约和任务创建，再进入 Playwright 保存链路。
