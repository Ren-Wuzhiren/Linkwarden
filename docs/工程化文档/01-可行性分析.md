# 可行性分析

## 技术可行性

- Java 17 + Spring Boot 可以承担 API、事务、鉴权和 Worker profile。
- MyBatis-Plus 适合当前关系模型，复杂任务领取 SQL 可直接手写。
- Playwright Java 可以执行页面渲染、全页截图和 PDF 导出。
- Jsoup 可以抽取标题、描述和链接；正文清洗需要限制 HTML 风险。
- MySQL `FOR UPDATE SKIP LOCKED` 支持多 Worker 安全抢占任务。
- MySQL 8 ngram FULLTEXT 可支持第一版中英文检索。
- 本地文件系统足够完成单机版本，存储接口为后续替换对象存储留出边界。

## 实现难点

- SSRF 与 DNS 重绑定防护。
- Playwright 页面超时、浏览器崩溃和资源回收。
- 同一链接重复点击时的幂等处理。
- 保存过程中部分格式成功、部分格式失败。
- 搜索索引与正文更新的一致性。
- Windows 开发环境与 Docker/Linux 部署环境差异。

## 时间可行性

建议按 6 个增量推进，每个增量 3-7 天。每轮必须完成“设计解释 -> 用户编码 -> Codex 审查 -> 测试 -> 文档 -> commit”，不以一次性写完代码为目标。

## 环境可行性

- 自有代码使用 Java 17、Maven 和 Vue。
- 上游参考源码使用隔离的 Node 20、Yarn 4.12.0 和 Docker 依赖。
- 上游已验证可通过 `http://localhost:3000` 启动；自有实现不依赖上游运行。

## 结论

技术上可行，但必须严格控制第一版边界。最大风险不是 CRUD，而是异步保存链路的失败治理。因此先完成任务状态机和可观测性，再接入 Playwright。
