# 协作模式与笔记规范

> **一句话速览**：本规范重新定义"谁写什么、笔记长什么样、注释怎么写、每轮对话给什么"，目标是把产出从"你能查"变成"你能懂"。🐋

## 📌 为什么要改

2026-10-11 那次把笔记改成了"知识产品"。

改的内容是一句一段、表格化、emoji 锚点、术语速查。

那次优化的是扫读速度，不是理解深度。

所以 2026-10-16 仍然读不懂。

量出来的数字说明问题不在字数。

| 指标 | Codex 写的技术笔记 | 用户写的源码研读 07 |
| --- | ---: | ---: |
| 总字符 | 15245 | 14216 |
| 平均句长 | 85 字 | 258 字 |
| 并列列表项 | 147 | 10 |
| 表格行 | 0 | 75 |

用户写的那篇句子长三倍，但读得懂。

原因有三条。

**第一条：并列断言太多。** 147 条 bullet，每条一个独立结论，读它需要同时记住一串互不相关的规定。

**第二条：前置概念欠账。** `四大件笔记/操作系统.md` 有一句话压了五个未解释的概念，读者要先补五个知识才能收到一条结论。

**第三条：句子拆短了，断言没拆。** 09 规范要求一句一段，照做之后句子变短，但每句话里的断言数量没有变。

还有一条事实要澄清：09 规范并没有要求写成 147 条 bullet。

它的块型优先序把表格排在最前，技术笔记出现 0 表格是执行背离了规范，不是规范的问题。

## 🧩 分工

| 角色 | 负责 |
| --- | --- |
| 用户 | 生产代码亲手实现；每轮回答收尾问题 |
| Codex | 设计契约、测试代码、文档与收尾、代码审查 |
| 双方共同 | 确认接口契约、数据模型、失败路径与验收标准 |

顺序是**实现先行**。

```text
1. Codex 给设计契约：类名、方法签名、规则、验收标准；不给参考实现
2. 用户按契约实现生产代码
3. Codex 读完后编写测试
4. 用户跑测试，双方修正
```

## 🧩 笔记规范

新笔记放在 `docs/学习笔记/`。

一条概念一个文件，文件名就是概念名。

`README.md` 是索引，三列：概念、一句话、学到它的阶段。

### 每个文件的五段

```text
# <概念名>

> 触发它的契机：<一句话，当时在做什么、被什么卡住>

## 它是什么、解决什么问题
## 怎么做的（含一个最小例子）
## 会踩的坑
## 我当时的理解
```

最后一段是用户的**原话，一字不改**。

讲解层由 Codex 写。

### 选材标准

三条全中才能写。

| 条件 | 说明 |
| --- | --- |
| 真的被它卡过 | 用户这一轮确实因此停顿或提问过 |
| 有复用价值 | 以后还会遇到，不是一次性配置 |
| 一个最小例子能说清 | 说不清说明还没到能记的粒度 |

### 数量上限

**40 条。**

要加第 41 条，必须先合并或删掉一条。

上限不是凑数的限制，是"少而能懂"的执行机制。

每轮最多新增 1～2 条。

宁可空着，也不为凑进度写笔记。

### 408 入口

每条笔记保留一行 `对应 408：<操作系统 / 网络 / 组成 / 数据结构>`。

`docs/四大件笔记/` 冻结，不再增写。

## 🧩 注释规范

每条注释写两段。

**第一句说这段在做什么。**

**第二句说为什么这么做、不那样做会怎样。**

旧规范只留了"为什么"，把新手最需要的"是什么"删掉了，这是缺陷源头。

具体规则：

- 取消 `[业务]`、`[Java]`、`[软件工程]`、`[408]`、`[排错]` 五个前缀；前缀的分类价值由笔记承接。
- 单条注释不超过 3 行。超过说明它属于笔记，不属于注释。
- `/** ... */` 用于类与公开方法的契约，`//` 用于方法内部；这条规则不变。
- 每个测试方法前保留一行 `// [测试意图] ...`。

## 🧩 对话规范

每轮回复包含且只包含三块。

```text
这轮你要做的动作（清单）
验收命令
收尾问题（2～3 个）
```

另外四条：

- 每个断言独立成句，不再用「：」「，」串两三个结论。
- 出现新术语当场给一句话解释，不假设用户已知。
- 讲解与设计理由去笔记或去设计稿，不在常规轮次里展开长文。
- 只有"用户要做决定"或"用户答不上问题"时才展开讲解。

收尾问题只用三种形式。

| 形式 | 例子 |
| --- | --- |
| 复述型 | 这一步我做了什么？ |
| 预测型 | 去掉 X 会怎样？ |
| 迁移型 | 你以前在哪见过类似的东西？ |

答不上就不写笔记，先补讲再重问。

## ✅ 验收与回退

跑完一个完整里程碑后评估。

| 编号 | 标准 |
| --- | --- |
| ① | 不查任何文档，用自己话讲出这一轮的核心概念（3 条里讲出 2 条） |
| ② | 新笔记里"我当时的理解"是自己的原话，且读得出"这就是我想说的" |
| ③ | 写生产代码时，至少独立提出过一个质疑或改进 |
| ④ | 不看参考实现，能把某个方法独立重写一遍 |

任一条不满足，回退。

回退成本已经控制住：

```text
三份旧笔记原样未动
AGENTS.md 的旧表述在 git 历史里
docs/学习笔记/ 整目录删掉不影响其他文档
```

- 三份旧笔记（`技术笔记`、`排错笔记`、`四大件笔记`）冻结：不删、不改、不增写。
