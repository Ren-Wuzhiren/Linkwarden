# 测试性能优化与技术亮点

## 背景

优化前的全量测试命令：

```powershell
mvn -pl backend test
```

优化前基线：

- 日期：2026-10-08
- 测试数量：86
- 总用时：`1 分 23 秒 177 毫秒`
- 结果：86 项通过，0 失败，0 错误，0 跳过

## 瓶颈分析

主要耗时来自 Testcontainers 集成测试。每个集成测试类都创建并启动一套 MySQL 和 Redis：

```text
AppUserMapperTest
SaTokenRedisIntegrationTest
AuthRegistrationIntegrationTest
AuthSessionIntegrationTest
```

优化前慢测试套件：

| 测试套件 | 耗时（秒） |
| --- | ---: |
| `AuthRegistrationIntegrationTest` | 23.51 |
| `AppUserMapperTest` | 17.63 |
| `AuthSessionIntegrationTest` | 17.27 |
| `SaTokenRedisIntegrationTest` | 15.61 |
| `AuthControllerTest` | 0.67 |
| `AuthServiceTest` | 0.41 |

四个集成测试套件合计约 74 秒，说明重复启动容器是主要瓶颈，而不是业务断言本身。

## 优化方案

新增测试支持类：

```text
backend/src/test/java/com/webcollector/support/SharedTestContainers.java
```

该类在同一个测试 JVM 中只创建并启动一套：

- MySQL 8.4
- Redis 7.4

各集成测试类通过统一的：

```java
SharedTestContainers.registerProperties(registry);
```

注册数据源和 Redis 属性，不再分别声明 `@Container`。

优化后：

- 每个 JVM 的 MySQL 启动次数：4 次 → 1 次
- 每个 JVM 的 Redis 启动次数：4 次 → 1 次
- 容器总启动次数：8 次 → 2 次
- 测试执行仍保持串行，优先保证隔离和可复现性

## 优化结果

在 Docker 镜像已存在、Docker Desktop 已启动的热环境下，使用 PowerShell Stopwatch 连续运行三次：

```powershell
$sw = [System.Diagnostics.Stopwatch]::StartNew()
mvn -q --no-transfer-progress -pl backend test
$sw.Stop()
$sw.Elapsed.TotalMilliseconds
```

| 运行 | 测试数量 | 失败 | 错误 | 跳过 | 耗时（毫秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第 1 次 | 86 | 0 | 0 | 0 | 38047 |
| 第 2 次 | 86 | 0 | 0 | 0 | 37116 |
| 第 3 次 | 86 | 0 | 0 | 0 | 37006 |

三次运行中位数：

```text
37116 ms ≈ 37.1 s
```

相比优化前基线：

```text
83177 ms → 37116 ms
减少：46061 ms
下降：约 55.4%
```

## 技术亮点表述

可以把这项优化表达为：

> 针对 4 个 Testcontainers 集成测试类重复启动 MySQL 和 Redis 导致的约 74 秒基础设施开销，抽取 JVM 级共享容器，将容器启动从 8 次降为 2 次；在测试数量和覆盖范围不变的前提下，将 86 项 Maven 全量测试的中位耗时从约 83.2 秒降至约 37.1 秒，减少约 55.4%。

这类优化的工程价值不是“让单条业务代码更快”，而是：

- 缩短本地开发反馈回路
- 降低 CI 中重复基础设施开销
- 保留真实 MySQL、Redis 和 Sa-Token 集成验证
- 不通过删除测试或跳过集成测试换取速度

## 局限与风险

- 数据只代表当前 Windows、Docker Desktop、已有镜像的热运行环境，不代表 CI 冷启动时间。
- 共享容器意味着测试类之间共享数据库和 Redis 实例，测试必须继续保持数据清理和隔离。
- 当前没有启用测试类并行执行，避免数据库和会话状态竞争。
- 容器原则上由 Ryuk 在 JVM 退出后清理，不依赖 `withReuse(true)` 的跨 JVM 持久复用。

## 后续可选优化

- 合并相同 `@SpringBootTest` 配置，进一步复用 Spring TestContext。
- 将单元测试与集成测试拆成不同 Maven 生命周期阶段，优先提供更快的单元测试反馈。
- 在确认隔离策略后，评估只对纯单元测试启用 JUnit 并行执行。
- 在 CI 中分别记录冷镜像和热镜像耗时，避免把本地热运行数字等同于流水线数字。
