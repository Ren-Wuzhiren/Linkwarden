# 业务与系统流程

## 保存链接流程

```mermaid
flowchart TD
  A[用户提交 URL] --> B{登录且参数合法}
  B -- 否 --> B1[返回 400/401]
  B -- 是 --> C[规范化 URL 并计算哈希]
  C --> D{用户已存在该 URL}
  D -- 是 --> D1[返回已有链接]
  D -- 否 --> E[创建 Link 和 CaptureJob]
  E --> F[返回等待抓取状态]
  F --> G[Worker 抢占任务]
  G --> H[SSRF 校验]
  H --> I{允许抓取}
  I -- 否 --> I1[任务失败并记录原因]
  I -- 是 --> J[Playwright 打开页面]
  J --> K[生成 HTML/PDF/截图]
  K --> L[抽取正文与元数据]
  L --> M[写资产记录并完成任务]
  M --> N[更新 Link 检索字段]
```

## 任务状态机

```mermaid
stateDiagram-v2
  [*] --> PENDING
  PENDING --> RUNNING: Worker 抢占成功
  RUNNING --> SUCCEEDED: 至少 HTML 或截图成功
  RUNNING --> PENDING: 失败且 attempt_count < 3
  RUNNING --> FAILED: 达到最大尝试次数
  FAILED --> PENDING: 用户手动重新采集
```

## 重试与恢复

- Worker 抢占任务时写入 `locked_by` 和 `locked_until`。
- 每次失败记录错误码和可读错误信息。
- 第 1、2 次失败分别等待 30 秒、120 秒；第 3 次失败标记为 `FAILED`。
- 定时扫描超过锁定时间仍为 `RUNNING` 的任务，将其恢复为 `PENDING`。
- 重新采集创建新 Job，旧资产保留；新 Job 全部成功后更新当前展示版本。

## 搜索流程

```mermaid
flowchart LR
  Q[搜索词] --> P[解析 tag: collection: before: after:]
  P --> S[MySQL ngram FULLTEXT + 条件过滤]
  S --> A[校验 user_id 和 collection owner]
  A --> R[返回链接和当前资产元数据]
```

## 失败场景

- URL 无法解析或指向私网：不进入浏览器，直接记录 `UNSAFE_URL`。
- 页面超时：终止浏览器操作，按普通失败重试。
- PDF 或 HTML 单格式失败：保留已成功资产，任务可标记部分成功。
- Worker 崩溃：锁过期后任务重新可见。
- 文件写入失败：事务中的资产记录不提交，任务进入重试。
