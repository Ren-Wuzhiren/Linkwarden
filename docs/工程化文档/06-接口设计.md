## 通用约定

- 基础路径：`/api/v1`
- 鉴权：`Authorization: Bearer <token>`
- Content-Type：`application/json`
- 时间：ISO 8601 UTC 字符串
- 分页：游标分页，返回 `nextCursor`
- 请求 ID：响应头 `X-Request-Id`，错误体中同时返回

成功响应：

```json
{
  "data": {},
  "message": "OK",
  "requestId": "..."
}
```

失败响应：

```json
{
  "code": "LINK_ALREADY_EXISTS",
  "message": "链接已存在",
  "details": {},
  "requestId": "..."
}
```

## 鉴权

### POST /auth/register

状态：已实现，阶段 `1.3`（旧 `1.4.3`）。

仅在 `app.auth.registration-enabled=true` 时可用；当前本地 profile 开启，其他环境默认关闭。

```json
{
  "username": "student",
  "email": "student@example.com",
  "password": "..."
}
```

字段规则：

- `username`：`@NotBlank`，规范化后 3 到 32 个字符。
- `email`：可选；空字符串和全角空白规范化为 `null`；非空时长度不超过 254 且必须符合邮箱格式。
- `password`：`@NotBlank`，长度 8 到 72；不执行 `strip()`，因为首尾空格可能是密码的一部分。
- 注册成功后只返回 `UserSummary`，绝不返回 `passwordHash`；成功响应使用 `201 Created`。

错误：注册关闭返回 `403 REGISTRATION_DISABLED`，用户名或邮箱冲突返回 409，数据库唯一冲突不允许原样泄漏。

### POST /auth/login

状态：已实现，阶段 `1.4`（旧 `1.4.4`）。

```json
{
  "username": "student",
  "password": "..."
}
```

返回 `token`、`tokenName`、`expiresAt` 和当前用户摘要。

### POST /auth/logout

状态：已实现，阶段 `1.4`（旧 `1.4.4`）。

注销当前 Token；重复注销返回成功。

### GET /auth/me

状态：已实现，阶段 `1.4`（旧 `1.4.4`）。

返回 `id`、`username`、`email` 和 `createdAt`。`UserSummary` 不包含 `passwordHash`。

无 Token、Token 过期、Token 被注销时返回：

```json
{
  "code": "AUTH_REQUIRED",
  "message": "请先登录",
  "details": {},
  "requestId": "..."
}
```

HTTP 状态码为 401。`details` 固定为空，不回显 Sa-Token 内部异常消息（例如具体是缺 Token 还是 Token 无效），避免向客户端泄漏认证实现细节。

## 链接与任务

状态：`M2.3` 已实现保存、列表、读取、更新和删除，五个接口全部带所有权隔离。URL 规范化与重复检测排在 `M2.5`，任务创建与轮询排在 `M2.6`。

### POST /links

状态：已实现基础保存（`M2.3`）。

```json
{
  "url": "https://example.com/article",
  "collectionId": 1,
  "tagIds": [1, 2],
  "title": "",
  "description": ""
}
```

`M2.3` 的实际行为：

1. 校验 `collectionId` 属于当前用户，不属于则返回 `404`。
2. 原样保存地址到 `original_url`，当前不做规范化、不计算哈希。
3. 返回 `201 Created` 与 `link` 摘要，暂不返回 `job`。

完整目标行为（后续里程碑）：

1. 规范化 URL 并计算哈希（`M2.5`）。
2. 相同用户下已存在时返回已有链接和 `409 LINK_ALREADY_EXISTS`（`M2.5`）。
3. 创建链接和 `PENDING` 任务（`M2.6`）。
4. 返回 `link` 和 `job`，不等待抓取完成（`M2.6`）。

请求体里的 `tagIds` 要等 `M2.4` 的 `link_tag` 落地后才会生效。

### GET /links

状态：已实现基础列表（`M2.3`），返回当前用户的全部链接，按 id 倒序，暂不分页。

完整目标行为（`M6.2`）：游标分页，查询参数 `collectionId`、`tagId`、`cursor`、`limit`（默认 20，最大 100）。

### GET /links/{id}

状态：已实现（`M2.3`），返回链接摘要；别人的链接一律 `404`。

完整目标行为：额外返回当前最新成功任务和资产元数据（`M5` 之后）。

### PATCH /links/{id}

状态：已实现（`M2.3`），允许修改标题、描述和所属集合；地址不可修改。

### DELETE /links/{id}

状态：已实现基础删除（`M2.3`），只删除链接自身那一行，返回 `200`。

完整目标行为：连带任务和资产记录一起删除，返回 `202`，物理文件异步清理（`M5` 之后）。

## 任务

### GET /jobs/{id}

```json
{
  "id": 1001,
  "linkId": 42,
  "status": "RUNNING",
  "attemptCount": 1,
  "maxAttempts": 3,
  "errorCode": null,
  "errorMessage": null,
  "assets": []
}
```

前端在 `PENDING/RUNNING` 时每 3 秒轮询，终态后停止。

## 资产

- `GET /assets/{id}/metadata`：返回 MIME、大小、SHA-256 和创建时间。
- `GET /assets/{id}`：鉴权后返回文件流。
- HTML 资产使用 `Content-Disposition: attachment`，不在同源内直接内联执行。

## 搜索

### GET /search

查询参数：

- `q`：标题、描述、正文、标签的普通搜索词。
- `tag`：标签精确过滤，可重复。
- `collectionId`：集合过滤。
- `before`、`after`：创建时间范围。
- `cursor`、`limit`。

返回链接与当前资产元数据，不返回完整 HTML 或正文。

## 健康检查

- `GET /api/v1/health/live`：只表示进程存活，不检查数据库和 Redis。
- `GET /api/v1/health/ready`：检查 MySQL 和 Redis；两个依赖都可用时返回 HTTP 200，任一不可用时返回 HTTP 503 和 `SERVICE_UNAVAILABLE`。

就绪成功响应：

```json
{
  "data": {
    "mysql": "UP",
    "redis": "UP"
  },
  "message": "服务已就绪",
  "requestId": "..."
}
```

就绪失败响应：

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "服务依赖未就绪",
  "details": {
    "mysql": "UP",
    "redis": "DOWN"
  },
  "requestId": "..."
}
```

## 错误码

已实现（与 `ErrorCode` 枚举一致）：

- `VALIDATION_ERROR`：400，请求体字段校验失败，`details` 为字段到消息的映射。
- `INVALID_REQUEST`：400，请求格式错误或参数类型不匹配。
- `UNAUTHORIZED`：401，通用未认证。
- `AUTH_REQUIRED`：401，缺失、过期或无效 Token；`GlobalExceptionHandler` 对 `NotLoginException` 的固定映射。
- `FORBIDDEN`：403。
- `NOT_FOUND`：404。
- `CONFLICT`：409。
- `REGISTRATION_DISABLED`：403，注册功能关闭。
- `USERNAME_ALREADY_EXISTS`、`EMAIL_ALREADY_EXISTS`：409，注册唯一字段冲突。
- `INTERNAL_ERROR`：500，兜底异常，响应不包含异常消息和堆栈。
- `SERVICE_UNAVAILABLE`：503，就绪检查失败。
- `AUTH_INVALID_CREDENTIALS`：401，登录时用户名或密码错误，不区分具体原因。
- `COLLECTION_NAME_ALREADY_EXISTS`、`COLLECTION_INBOX_PROTECTED`：409，集合名称冲突与 Inbox 删除保护。
- `TAG_NAME_ALREADY_EXISTS`：409，标签名称在同一用户下冲突。
- `COLLECTION_NOT_EMPTY`：409，集合里还有链接时拒绝删除。

后续阶段计划新增（尚未实现，避免提前定义未使用的枚举值）：

- `LINK_ALREADY_EXISTS`、`CAPTURE_IN_PROGRESS`：409。
- `UNSAFE_URL`：422。
- `CAPTURE_FAILED`：任务失败状态，不直接用作 HTTP 500。
