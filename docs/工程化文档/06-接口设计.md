## 通用约定

- 基础路径：`/api/v1`
- 鉴权：`Authorization: Bearer <token>`
- Content-Type：`application/json`
- 时间：ISO 8601 UTC 字符串
- 分页：游标分页，返回 `nextCursor`
- 请求 ID：响应头 `X-Request-Id`，错误体中同时返回

成功响应：

```json
{
  "data": {},
  "message": "OK",
  "requestId": "..."
}
```

失败响应：

```json
{
  "code": "LINK_ALREADY_EXISTS",
  "message": "链接已存在",
  "details": {},
  "requestId": "..."
}
```

## 鉴权

### POST /auth/register

状态：已实现，阶段 `1.3`（旧 `1.4.3`）。

仅在 `app.auth.registration-enabled=true` 时可用；当前本地 profile 开启，其他环境默认关闭。

```json
{
  "username": "student",
  "email": "student@example.com",
  "password": "..."
}
```

字段规则：

- `username`：`@NotBlank`，规范化后 3 到 32 个字符。
- `email`：可选；空字符串和全角空白规范化为 `null`；非空时长度不超过 254 且必须符合邮箱格式。
- `password`：`@NotBlank`，长度 8 到 72；不执行 `strip()`，因为首尾空格可能是密码的一部分。
- 注册成功后只返回 `UserSummary`，绝不返回 `passwordHash`；成功响应使用 `201 Created`。

错误：注册关闭返回 `403 REGISTRATION_DISABLED`，用户名或邮箱冲突返回 409，数据库唯一冲突不允许原样泄漏。

### GET /auth/me

状态：未实现，下一步为 `1.4`。

返回 `id`、`username`、`email` 和 `createdAt`。`UserSummary` 不包含 `passwordHash`。

无 Token、Token 过期、Token 被注销时返回：

```json
{
  "code": "AUTH_REQUIRED",
  "message": "请先登录",
  "details": {},
  "requestId": "..."
}
```

HTTP 状态码为 401。`details` 固定为空，不回显 Sa-Token 内部异常消息（例如具体是缺 Token 还是 Token 无效），避免向客户端泄漏认证实现细节。

## 集合

- `GET /collections`：返回当前用户的全部集合和链接数量。
- `POST /collections`：创建集合，名称在用户范围内唯一。
- `PATCH /collections/{id}`：修改名称和描述。
- `DELETE /collections/{id}`：拒绝删除 Inbox；其他集合存在链接时返回 `409`。

## 链接与任务

### POST /links

```json
{
  "url": "https://example.com/article",
  "collectionId": 1,
  "tagIds": [1, 2],
  "title": "",
  "description": ""
}
```

行为：

1. 规范化 URL 并计算哈希。
2. 相同用户下已存在时返回已有链接和 `409 LINK_ALREADY_EXISTS`。
3. 创建链接和 `PENDING` 任务。
4. 返回 `link` 和 `job`，不等待抓取完成。

### GET /links

查询参数：

- `collectionId`
- `tagId`
- `cursor`
- `limit`，默认 20，最大 100

### GET /links/{id}

返回链接、当前最新成功任务和资产元数据。

### PATCH /links/{id}

允许修改标题、描述、集合和标签，不允许直接修改 `normalizedUrl`。

### DELETE /links/{id}

删除链接及其任务和资产记录，返回 `202`；物理文件异步清理。

### POST /links/{id}/recapture

为已有链接创建新的 `PENDING` 任务。已有任务处于 `PENDING/RUNNING` 时返回 `409 CAPTURE_IN_PROGRESS`。

## 标签

- `GET /tags`：返回标签和链接数量。
- `POST /tags`：创建标签。
- `PATCH /tags/{id}`：修改名称。
- `DELETE /tags/{id}`：删除标签及链接关联，不删除链接。
- `PUT /links/{id}/tags`：替换链接标签集合。

## 任务

### GET /jobs/{id}

```json
{
  "id": 1001,
  "linkId": 42,
  "status": "RUNNING",
  "attemptCount": 1,
  "maxAttempts": 3,
  "errorCode": null,
  "errorMessage": null,
  "assets": []
}
```

前端在 `PENDING/RUNNING` 时每 3 秒轮询，终态后停止。

## 资产

- `GET /assets/{id}/metadata`：返回 MIME、大小、SHA-256 和创建时间。
- `GET /assets/{id}`：鉴权后返回文件流。
- HTML 资产使用 `Content-Disposition: attachment`，不在同源内直接内联执行。

## 搜索

### GET /search

查询参数：

- `q`：标题、描述、正文、标签的普通搜索词。
- `tag`：标签精确过滤，可重复。
- `collectionId`：集合过滤。
- `before`、`after`：创建时间范围。
- `cursor`、`limit`。

返回链接与当前资产元数据，不返回完整 HTML 或正文。

## 健康检查

- `GET /api/v1/health/live`：只表示进程存活，不检查数据库和 Redis。
- `GET /api/v1/health/ready`：检查 MySQL 和 Redis；两个依赖都可用时返回 HTTP 200，任一不可用时返回 HTTP 503 和 `SERVICE_UNAVAILABLE`。

就绪成功响应：

```json
{
  "data": {
    "mysql": "UP",
    "redis": "UP"
  },
  "message": "服务已就绪",
  "requestId": "..."
}
```

就绪失败响应：

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "服务依赖未就绪",
  "details": {
    "mysql": "UP",
    "redis": "DOWN"
  },
  "requestId": "..."
}
```

## 错误码

已实现（与 `ErrorCode` 枚举一致）：

- `VALIDATION_ERROR`：400，请求体字段校验失败，`details` 为字段到消息的映射。
- `INVALID_REQUEST`：400，请求格式错误或参数类型不匹配。
- `UNAUTHORIZED`：401，通用未认证。
- `AUTH_REQUIRED`：401，缺失、过期或无效 Token；`GlobalExceptionHandler` 对 `NotLoginException` 的固定映射。
- `FORBIDDEN`：403。
- `NOT_FOUND`：404。
- `CONFLICT`：409。
- `REGISTRATION_DISABLED`：403，注册功能关闭。
- `USERNAME_ALREADY_EXISTS`、`EMAIL_ALREADY_EXISTS`：409，注册唯一字段冲突。
- `INTERNAL_ERROR`：500，兜底异常，响应不包含异常消息和堆栈。
- `SERVICE_UNAVAILABLE`：503，就绪检查失败。

后续阶段计划新增（尚未实现，避免提前定义未使用的枚举值）：

- `AUTH_INVALID_CREDENTIALS`：401。
- `LINK_ALREADY_EXISTS`、`CAPTURE_IN_PROGRESS`：409。
- `UNSAFE_URL`：422。
- `CAPTURE_FAILED`：任务失败状态，不直接用作 HTTP 500。
